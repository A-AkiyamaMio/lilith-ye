# 莉莉丝档案同步到公开站设计规格

日期：2026-10-06  
目标站：`lilith-ye.vip`  主题站  
源站：`lilith-private-archive-mio.a835979020z.chatgpt.site` 私人 Wiki

## 目标

把源站已经定稿的莉莉丝核心设定、视觉资产和档案入口同步到目标站，同时保留目标站已有的“公开展览 + 受邀档案馆”定位。公开访问者看到的是经过筛选的角色展示；完整设定、提示词和修订记录只出现在档案馆边界内。

## 不做的事

- 不把源站的登录、注册申请、审核台、D1 数据库或后台管理系统搬到目标站。
- 不把源站的密码、会话、环境变量、数据库内容或内部接口写入目标仓库。
- 不删除目标站现有公开页面和动效框架；只替换占位内容、补齐档案页面和接入必要资源。
- 不把私密档案条目加入公开 JSON、公开站点地图或公开页面的预加载脚本。

## 内容分层

### 公开层

公开层只使用源站中适合展示的稳定设定：莉莉丝是成年角色、清纯但带危险感的目光、暗红虹膜内圈、浅蓝乳白色五角星吊坠、高马尾/披发状态，以及现代服装和展览世界观。公开页接入经过筛选的角色主视觉、肖像和吊坠图，不展示完整提示词或内部修订细节。

目标文件主要包括：

- `src/pages/index.astro`
- `src/pages/lilith.astro`
- `src/pages/gallery.astro`
- `src/pages/world.astro`
- `content/public/`
- `data/gallery.json`
- `public/assets/`

### 私密档案层

`/archive/*` 保留完整档案入口，内容来源对应源站的外观、资产、提示词和修订记录。档案页面使用 `ArchiveLayout.astro`，保持 `noindex,nofollow`，不进入公开导航和公开数据集合。

私密媒体若需要从页面引用，必须放入单独的私密媒体路径，并要求 Cloudflare Access 同时保护 `/archive/*` 和该媒体路径；在保护规则未确认前，不发布包含私密媒体的页面。

## 页面与数据流

1. 从源站读取最新已保存版本，使用 `content/lilith/appearance.ts`、`assets.ts`、`prompts.ts`、`revisions.ts` 和 `public/` 下的视觉资产作为迁移输入。
2. 在目标 Astro 站建立单一的公开角色摘要数据，公开页和档案页都从这个摘要读取稳定字段，避免同一设定在多个页面漂移。
3. 公开页显示摘要和经过筛选的视觉内容；档案页显示完整字段、母图职责、提示词入口和修订记录。
4. 不把源站的 Next/D1 运行时引入目标站；目标仍由 Astro 静态构建并通过 Cloudflare Pages 发布。

## 视觉与交互

- 保留目标站目前的米白、暗红、冷蓝灰色调、衬线标题和轻量入场动效。
- 将占位视觉替换为源站当前确认的角色/吊坠资产；画廊卡片保留悬停、渐显和移动端布局。
- 对 `prefers-reduced-motion: reduce` 保持无动画降级。
- 移动端继续使用单列布局，图片使用明确的 `alt` 文本，键盘焦点保持可见。

## 隐私与发布闸门

发布前必须检查：

- 公开构建产物中没有提示词全文、修订内部说明、私密 Markdown 或源站登录接口。
- `/archive/*` 的 Cloudflare Access 规则已存在；若规则不能从当前环境验证，则只发布公开层，档案页面留在本地分支等待确认。
- 私密媒体不通过公开 `/assets/` 路径暴露。

## 验证

- 运行 `npm run build`，确认 Astro 构建成功。
- 运行 `npm test`，确认现有内容与动效测试通过。
- 检查构建结果中的公开路由、档案路由、站点地图和资源路径。
- 检查桌面与移动布局、键盘访问、减少动效模式和图片加载。
- 先在 `redesign/lilith-gallery` 完成提交，再将经过验证的提交合入 `main` 并推送，让 Cloudflare Pages 自动部署。

## 取舍

选择“内容与视觉同步”而不是整站照搬，是为了保留目标站已经建立的公开/私密边界和静态部署可靠性；源站继续作为设定控制中心，目标站负责展示，不让两个站各自维护一套登录和数据库逻辑。
